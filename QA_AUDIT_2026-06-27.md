# AURIS360 QA Audit - 27 June 2026

## Scope
- Live app reviewed at https://auris-360.vercel.app/
- Login used: codex@sephsconsulting.local
- Password was changed to the user-provided value during first login.
- Tested visible modules and inspected shipped source for hidden modules and workflows.

## Executive Summary
AURIS360 has strong module coverage and many of the requested safety workflows are already present or partially implemented: incident reporting, BBS, chemical register with SDS parsing, fleet, ATEX, permit to work, fire certificates, training, PPE, meetings, notifications, branding, and guided risk-assessment builders.

The biggest rollout risks are not missing features; they are consistency, access control, navigation reliability, and workflow completion. Some modules are hidden by module access rules even for the test account, some pages still use card layouts rather than tables, and several action buttons have icons only with no accessible label.

## Blockers Before Client Pilot
1. Module access mismatch
   - The test account showed only a limited visible sidebar even after the internal role value was `sephs_admin`.
   - Hidden modules still exist in the app: Risk Assessment, Legal Compliance, Master Action Plan, Tools, Contractors, People, Companies, Document Control, Environmental / ESG, Noise Survey, Occupational Health.
   - Recommendation: verify the logged-in profile role, company context, and `companies.module_access`. SEPHS admin should have a clear "view all modules" mode independent of client pilot module limits.

2. Settings and Integrations navigation issue
   - During live scan, clicking `Integrations` and `Settings` resulted in the Users & Roles page staying active.
   - Recommendation: retest after closing any open user edit/invite panel and fix navigation if reproducible.

3. Delete confirmation blocks automation and creates a weak UX
   - Chemical delete uses a native browser `confirm()` dialog. It blocked the QA automation tab.
   - Recommendation: replace native confirm dialogs with in-app confirmation modals that have clear `Cancel` and `Delete` buttons.

4. Some modules depend on hidden source modules
   - Fleet actions route to Tools and ESG (`fleetNewVehicle`, `fleetFuelNew`), but Tools/ESG were not visible in the sidebar for the test account.
   - Recommendation: if Fleet is enabled for a client, required supporting modules/actions must also be accessible or embedded directly in Fleet.

## Module Findings

### Dashboard / Executive Dashboard
- Good direction for management overview.
- Improve by making dashboard cards always route to accessible pages only. Some dashboard cards point to hidden modules such as Legal, ESG, Audit, People, depending on access.
- Recommendation: show a small "module not enabled" message or hide cards for disabled modules.

### Incident Management
- Strong structure: register, report, investigation, corrective actions, evidence, statistics.
- Employee form should remain simplified:
  - Employee reports should not see severity, regulatory notification, assignment, root cause, or investigation controls.
  - Supervisor/HSE Manager should complete classification, severity, assignment, investigation and root cause after submission.
- Recommendation: split incident into workflow views:
  - Employee quick report
  - Supervisor triage
  - HSE investigation
  - Admin reopen/release controls

### BBS Observations
- Good separation of observation types.
- Should be table-first for register, with a simple mobile form.
- Recommendation: names, department, location, and action owner should be dropdown/autocomplete from People/Sites.

### Chemical Control
- Create/update/reopen works for the previously failing exposure fields.
- Delete could not be completed in automation because native confirmation blocked the tab.
- Action button in table is icon-only with no visible label/title/aria-label.
- Recommendation: add labeled actions (`View/Edit`, `Delete`) and in-app confirmation modal. Remove/cleanup `QA TEST Chemical Cleaner` if still present.

### Permit to Work
- Source includes many good controls: permit types, smart checks, RA/MS dropdowns, issuer auto-fill, approver settings, gas tests, isolation, activity log.
- Remaining risks:
  - Approval settings may be hidden if Settings page access/navigation fails.
  - Permit receiver/site supervisor is still free text.
  - Team members are free text.
  - Some PTW supporting references depend on other modules being accessible.
- Recommendation: make receiver, issuer, approvers, gas tester, isolation authority, and team members dropdown/autocomplete from People/Users.

### Fleet Management
- Table layout exists and links vehicles to inspections, fuel logs and incidents.
- Add/edit/check/fuel actions route to Tools and ESG modules.
- Recommendation: either enable Tools/ESG with Fleet or bring the required forms inside Fleet to avoid dead-end navigation.

### ATEX Areas
- Table/register exists with zones, controls, inspection due, status, links to RA and PTW.
- Recommendation: add direct dropdown links to equipment, RA, permit type, responsible person, and inspection schedule.

### Fire Certificates
- Table-like register exists.
- Recommendation: link certificate premises/site to Companies/Sites and fire equipment records; add expiry notification recipients.

### Master Action Plan
- Source and previous UI indicate table/list functionality.
- Recommendation: make MAP the central action table for every module, with source links, owner dropdown, due date, status, escalation, and proof-of-close evidence.

### Legal Compliance
- Source includes legal register and PDF import style tools.
- Recommendation: every Act/regulation should import into structured rows:
  - legislation title
  - prefix
  - section/ref
  - requirement
  - category
  - obligation type
  - responsible role/person
  - compliance status
  - evidence
  - linked actions
- Add bulk delete by legislation and bulk section selection.
- Sort sections numerically by ref, not plain text.

### Training / PPE / Meetings / SOP
- Modules are present and visually accessible in the current account.
- Recommendation: all person fields should use People/Users dropdowns; all certificates/documents should link to Document Control.

## Cross-Module Improvements
1. People directory as the source of truth
   - Replace typed names with dropdown/autocomplete for assignee, investigator, approver, tester, trainer, attendees, permit receiver, exposed persons, and responsible persons.

2. Sites/Departments as controlled lists
   - Replace free text location/department where practical.
   - Keep "other / specific location" as a detail field.

3. Document Control integration
   - RA, SOP, Method Statement, MSDS/SDS, permits, certificates and evidence should be linked documents, not isolated uploads.

4. Notification routing
   - Settings should define recipients by event type, severity and module:
     - incidents
     - high-risk chemical
     - PTW pending approval
     - overdue action
     - certificate expiry
     - failed RCD test
   - WhatsApp can be added later via provider such as Twilio or WhatsApp Business Cloud API, but email should remain the reliable first channel.

5. Record locking and release
   - Employee-submitted incident should become read-only to employee.
   - Submitted investigation should become read-only to manager/supervisor.
   - Admin should have "release for amendment" with reason, audit trail, and expiry.

6. Replace native browser dialogs
   - Use in-app modals for delete/release/submit confirmations.
   - This improves mobile, accessibility, and testability.

7. Table-first module pattern
   - Every module should use:
     - metrics strip
     - search/filter bar
     - table/register
     - row drawer/detail
     - clear create/edit form
     - export/print

## Suggested Rollout Priority
1. Fix access/navigation first.
2. Stabilise the 3 pilot modules: Incident, BBS, KPIs.
3. Stabilise PTW, Chemical, Legal, MAP because they are high-value and high-risk.
4. Standardise all person/location/document fields.
5. Add audit trail, locking and admin release.
6. Add notification routing and retry dashboard.
7. Do mobile QA on Android Chrome, iPhone Safari, and iPad.
